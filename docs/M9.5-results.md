# M9.5 results

Tested on 8 November 2026 on Windows, Arch and Ubuntu (WSL2) on the development PC. This was built overnight, without anyone trying it by hand.

**It has never talked to the real Claude API.** No API key was available, and a real call costs money, so every test uses made-up replies in the API's format. The first real summary is the most important test still to do.

You can now get a summary of a publication from Claude, using your own API key. It's off until you enter a key, and only ever happens when you ask, for one publication at a time.

## How it works

1. **Asking:** choose **Summarize with Claude...** in the details panel or on the right-click menu.
2. **Choosing:** the dialog lists exactly what will be sent, with a model (Claude Sonnet 5.5 by default), an effort level (High by default) and an estimated cost that changes as you choose. Nothing about the publication has been sent yet.
3. **Reading the result:** the summary has its five sections: aim and background, methodology, results, limitations, and conclusion and discussion. Above it, it says what it was based on, and below it are the sources it read and the actual cost.
4. **Deciding:** **Accept** keeps it in the details panel. **Discard** keeps nothing.
5. **Last resort:** **Send the paper to Claude...** says what will leave the computer, restates what's been spent and gives a new estimate. Only its own confirmation sends anything.

## What's sent

The first request sends the title, authors, year, journal, DOI, URL and similar details, but not your notes, tags, abstract or file. Claude is given Anthropic's web search and web fetch tools to find the paper, limited to 3 searches and 2 pages read.

When you send the paper:

- **A PDF** goes as it is, up to about 23 MB and 600 pages.
- **Other formats** send their extracted text.
- **An article** sends only the text of its own pages, not the whole volume.
- **Anything too large** is refused with an explanation, and is never cut short to fit.

## Keeping a summary honest

Claude is told to use only what it read, to say when a section isn't covered, and to treat what it reads as material and not as instructions.

- **What it's based on:** the result says whether Claude read the full text, only the abstract, other sources or nothing, and whether it was sure it had the right paper.
- **Sources:** only what it read or cited is listed, not everything a search turned up.
- **Labelling:** a kept summary is marked as generated, with the model and date, and is kept apart from the abstract and your notes. It never changes a publication's details.
- **Unexpected replies:** a reply that doesn't follow the format is kept whole, so nothing is lost.

## The API key

The key is kept in the operating system's credential store through QtKeychain. If there's no store, as on a Linux system with no secret service, it's held in memory until the app closes, and **File > Claude API key...** says so. It's never in the database, settings or exports. A test searches every file a library writes for it.

It only goes in the header of a request to Anthropic, and those requests don't follow redirects, so it can't be passed on to another host. A key Anthropic refuses is forgotten, and asked for again.

On Linux, it reaches GNOME's keyring through the system's libsecret, which isn't bundled in the AppImage. A build without libsecret still works, with a warning, but the key then lasts only until the app closes on those desktops.

## Costs

Prices were taken from Anthropic's pricing page on 7 November 2026, and are built into the app with that date shown:

|---|---|---|
| Claude Sonnet 5.5 | $2 | $10 |

| Claude Haiku 5.5 | $0.10 ($0.50 over 100,000 tokens) | $0.50 ($2.50) |

Web search costs $10 per 1,000 searches, and web fetch has no charge beyond the tokens it reads.

**The estimates are my judgement and haven't been checked against real use.** In particular, how much effort adds to the output, and how much a typical search reads, are guesses. Please compare the estimates with real costs and tell me if they're off.

Other models your account can use are listed from Anthropic, and marked as having no known price, with no estimate.

## How it differs from the plan

- **Token counting isn't used for the estimate.** The plan had Anthropic's token counting give the input size. That would send the publication's details before you'd confirmed, so the estimate is worked out on this computer instead.
- **QtKeychain is built from source,** pinned like libmobi, and nothing was installed. You'd agreed to installing the package, but a packaged copy is tied to its distro's Qt, which wouldn't match the Qt 6.12 held on Windows and Ubuntu.
- **The model list asks Anthropic when the dialog opens,** if a key is saved. That only sends the key, and nothing about any publication.
- **The basic web tools are used,** without dynamic filtering, because they're predictable and available on every model offered.

## Problems testing found

- **Sending a non-PDF sent nothing.** A number overflowed while working out how many pages to read, so the text came back empty. A test caught it.
- **QtKeychain wouldn't build with MinGW,** because it assumes Windows means Microsoft's compiler. Its flag is now removed as it's fetched (`cmake/KeychainPatch.cmake`).

## How it's been tested

- **Automated:** all 16 test programs pass on all three platforms. The new `test_summary` covers what's sent, reading replies, costs, every kind of failure, and each step of the dialog, using a fake connection. It also uses the real network code against a server inside the test, including that a redirect isn't followed.
- **Confirmation:** tests check that nothing about the publication is sent before you confirm, and that the paper is never sent without its own confirmation.
- **Your files aren't changed:** the test compares the file's hash before and after.
- **AppImage:** it builds on Ubuntu with QtKeychain in it, and starts.
- **By eye:** pictures of the dialog, using an offscreen window with a poor fallback font.
- **Not tested yet:**
  - **The real Claude API.** The request's format, the web tools, costs, and how good the summaries are have all only been tested against what the documentation says.
  - **The real credential store.** Tests use a stand-in, so they don't leave anything in your Windows credentials.
  - **By hand in the real window.**

## Known limits

- **Cancelling doesn't stop what's already been sent.** It stops waiting for it, and the dialog says it may still be charged.
- **One summary per publication.** A new one you accept replaces the old.
- **Summaries are one at a time.** There's nothing for doing many at once, on purpose, given the cost.
- **Prices are built in,** so they'll go out of date, and the dialog shows when they were checked.
- **A long wait** shows only a progress bar, since a request runs for up to 10 minutes with nothing to report until the end.
- **M11's export** needs to include kept summaries, which the plan already says. The key is never included.
