# Speech in each package (1.4.0, step 0)

What reading aloud needs on each platform, found on 11 November 2026 with a small probe program that listed Qt TextToSpeech's engines and voices, synthesised a sentence without playing it, and spoke two queued sentences. Read aloud must work in every package, and the self-test must be able to prove it without a sound card.

## Windows (MSYS2, Qt 6.12.0)

- `mingw-w64-ucrt-x86_64-qt6-speech 6.12.0` has the `sapi` and `mock` engines, with no `winrt`. It needs `qt6-multimedia`, which pulls in `qt6-multimedia-ffmpeg`, `qt6-shadertools` and FFmpeg for building. These are new packages only, and nothing installed is upgraded. Name them explicitly, since `IgnorePkg` holds `qt6-*`.
- `sapi` is ready at once with the system's voices. It can speak, pause and resume, report word by word and synthesise. `aboutToSynthesize` fires once for each queued sentence.
- It works with only Windows' own folders on PATH when deployed with `windeployqt6 --skip-plugin-types ...,multimedia`. The package gains `Qt6TextToSpeech.dll`, `Qt6Multimedia.dll` and `texttospeech/qtexttospeech_sapi.dll`, and no FFmpeg DLLs.
- CI: add `qt6-speech` and `qt6-multimedia` to the MSYS2 lists in `windows.yml` and `windows-package.yml`. Check that a Windows runner has a SAPI voice before the self-test requires one.

## Linux: flite everywhere

Flite (CMU's, under a BSD-like licence) works without a daemon or a sound card, so it is the voice every Linux package can count on. Speech-dispatcher's voices are used where the system has them.

**Qt's flite engine only finds voice libraries in fixed system folders.** It reads `LD_LIBRARY_PATH` from a default-constructed `QProcessEnvironment`, which is always empty. So the voices a Flatpak keeps in `/app/lib`, or an AppImage in its own `usr/lib`, are never found. It also goes by the names of voices already listed in the process, though: for each, it loads `libflite_cmu_us_<name>.so.1` by its soname, registers the voice, and unregisters it, freeing it, when the engine goes. So on Linux Papertrail links the voice's library, so it's already loaded wherever it was found, and lists only a stand-in voice named `slt` (`new_voice()` and `flite_add_voice`) before making a `QTextToSpeech("flite")`. Listing the real voice, from `register_cmu_us_slt`, worked once, but the engine freed it on going, and the next engine made crashed on the list (found by `test_library_ui` on Arch). With the stand-in, two engines one after the other were each ready in the Flatpak's sandbox. It speaks through Qt Multimedia, so each package needs a multimedia backend.

Flite only has US English voices. With the locale `C` or a language it lacks, the engine has no voice until `setLocale(en_US)` is set, so Papertrail chooses a locale that has voices.

- **Arch:** `qt6-speech 6.12.0` has the `flite` and `speechd` engines, with `flite` and `speech-dispatcher` optional. It worked with `flite 2.2` and `qt6-multimedia` (the FFmpeg backend). It synthesised, and reported each sentence. The `PKGBUILD` depends on `qt6-speech`, `qt6-multimedia` and `flite`, with `speech-dispatcher` optional.
- **Ubuntu CI and the AppImage (Qt's own 6.12.0 from aqtinstall):**
  - `aqt install-qt ... -m qtspeech qtmultimedia` gives only the `speechd` and `mock` engines, plus the FFmpeg multimedia plugin with Qt's own LGPL FFmpeg.
  - The flite engine has to be built from `qtspeech-everywhere-src-6.12.0.tar.xz` (SHA-256 `9a60ce5bee54a9343740feab2582bffb996812f43d6c5585aade26dbd04933db`) with `qt-configure-module`. That needs `flite1-dev` and `libxkbcommon-dev`. Built that way, it worked.
  - The AppImage bundles that engine, `libflite`, `libflite_usenglish`, `libflite_cmulex` and `libflite_cmu_us_slt`, `Qt6TextToSpeech`, `Qt6Multimedia`, and the FFmpeg plugin with its libraries.
  - The `speechd` engine fails to load where `libspeechd` is missing, which is only a warning.
- **Flatpak (KDE 6.11 runtime):**
  - The runtime has `Qt6TextToSpeech` 6.11.3 but only the `mock` engine, and no flite. It does have the FFmpeg and GStreamer multimedia plugins, with PulseAudio and PipeWire.
  - The manifest builds flite 2.2 (`https://github.com/festvox/flite/archive/refs/tags/v2.2.tar.gz`, SHA-256 `ab1555fe5adc3f99f1d4a1a0eb1596d329fd6d74f1464a0097c81f53c0cf9e5c`, `--enable-shared`, `--with-audio=none`, serially). It also builds qtspeech 6.11.3 (`qtspeech-everywhere-src-6.11.3.tar.xz`, SHA-256 `cfadb37721f20c2dc85926a1edbf6c165d9162ea38ccdb6cbc4466109a21578c`), whose flite engine lands in `/app/lib/plugins/texttospeech`, on `QT_PLUGIN_PATH`.
  - Sound needs `--socket=pulseaudio`.
  - Speech-dispatcher's voices would also need its client library built in the manifest, and `--filesystem=xdg-run/speech-dispatcher:ro`. That's left for later: flite is enough to read aloud.

## What was done (step 6)

- Windows: `qt6-speech` and `qt6-multimedia` in both MSYS2 workflows, deployed with `--skip-plugin-types ...,multimedia`, and the package fails if `qtexttospeech_sapi.dll` is missing.
- Arch: the `PKGBUILD` depends on `qt6-speech`, `qt6-multimedia` and `flite`, with `speech-dispatcher` optional, and so do `arch.yml` and `sanitizers.yml`.
- Ubuntu CI: `modules: 'qtspeech qtmultimedia'` and `flite1-dev`.
- AppImage: `-m qtspeech qtmultimedia`, `flite1-dev libxkbcommon-dev`, `packaging/linux/build-qt-flite.sh` before building, and the build fails if the flite engine isn't in the AppDir.
- Flatpak: `flite` and `qtspeech` modules before Papertrail's, and `--socket=pulseaudio`.
- Every package's self-test requires a sentence to be made into sound.

## For the self-test

`synthesize()` worked with `sapi` and `flite` everywhere, with no sound card (WSL has none), so the self-test can ask for a sentence's audio and check that some came back.
