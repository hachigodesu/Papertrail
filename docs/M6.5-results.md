# M6.5 results

Tested on 7 November 2026 on Windows, Arch and Ubuntu (WSL2) on the development PC.

You can now gather publications into collections, for something like a project. Choosing one in the filter sidebar narrows the library to it, without the clutter of everything else.

## How it works

- **Finding them:** **Collections** is the first section of the filter sidebar. Each one is listed with a tick box and a live count, like the other filters.
- **Creating:** right-click **Collections** in the sidebar and choose **New collection...**. You can also select publications, right-click them and choose **Add to collection > New collection...**.
- **Adding:** select any number of publications, right-click them and choose **Add to collection**. A collection already holding them is ticked and can't be chosen again. If only some are in it, it says how many.
- **Viewing:** tick a collection. This combines with the type tabs, search and other filters. Ticking several shows what's in any of them, and **Clear** goes back to everything.
- **Removing:** right-click a publication and choose **Remove from collection**, whatever filters are on. This appears only if it's in one, and it stays in the library.
- **Renaming and deleting:** right-click a collection in the sidebar. Deleting asks first, with Cancel as the default, and only deletes the grouping, never its publications.
- **In the details panel:** a publication shows which collections it's in.

A publication can be in any number of collections, and adding one never moves or copies its file. Names must be different, ignoring case.

### With the rest of the library

- **Removed folders:** a publication hidden with its folder keeps its place in its collections, and is back in them when the folder returns.
- **Combining and separating:** a combined publication is in the collections of both. A separated format stays in the same collections as the publication it came from.
- **Deleting details:** a publication that's deleted leaves its collections.

## How it differs from the plan

The plan had each collection opening in a tab of its own. I built that first, but you asked for them to be navigated through the sidebar instead, so the tabs were removed before anything was committed, and the plan now describes the sidebar.

## How it's been tested

- **Automated:** all 12 test programs pass on all three platforms. The new tests cover the database, the queries and the window, including choosing, combining and clearing the filter, and the delete confirmation.
- **Speed:** with a collection of 5,000 in a 100,000-publication library, on Windows with a release build, results take 11 ms by title, 12 ms newest first, and 25 ms for a search, against the 100 ms target.
- **By eye:** a picture of the sidebar, using an offscreen window with a poor fallback font.
- **Not tested yet:**
  - **By hand in the real window.**
  - **On a Linux desktop by hand,** which is left until M12.
  - **A very large bulk add in the real window.** It runs in the background like bulk tagging, and the tests add only a few at a time.

## Known limits

- **There's no drag and drop.** Adding is through the right-click menu.
- **With more than 1,000 selected,** the right-click menu doesn't work out what's already in each collection, because that would hold up the window. It offers every collection for both adding and removing, and either is safe to repeat.
- **Articles aren't included with their volume.** Adding a volume adds only the volume, and articles have to be added themselves. This will matter once M7 adds articles, and may need revisiting then.
- **Collections can't be nested,** unlike tags.
- **M11's export** needs to include collections. They have permanent IDs for this, and it's already in the plan.
